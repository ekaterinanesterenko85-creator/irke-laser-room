# План: админ-панель для управления сайтом «Ирке LaserRoom»

## Цель
Дать вам и Ирке возможность самостоятельно менять на сайте всё содержимое: цены и услуги, фотографии, условия акции, контакты, адрес и любые тексты — без обращения к разработчику.

## Как это будет работать

1. Вы заходите на страницу входа `/admin`, вводите почту и пароль.
2. Открывается панель управления с разделами (слева меню, справа форма).
3. Меняете значение, нажимаете «Сохранить» — изменение сразу видно на сайте.
4. Регистрация закрыта: два аккаунта (ваш и Ирке) создаются заранее, оба с полными правами.

## Разделы админ-панели

### Услуги и цены
- Список отдельных зон и комплексов в двух вкладках.
- Для каждой позиции: название, цена, описание, бейдж («Популярный» и т.п.), порядок в списке, показывать/скрыть.
- Кнопки «Добавить услугу» и «Удалить».
- Порядок меняется стрелками вверх/вниз.

### Акция
- Заголовок акции, цена по акции, обычная цена, описание условий, срок действия.
- Переключатель «Показывать акцию на сайте» — если выключить, блок и кнопка в первом экране скрываются.

### Фотографии
- Загрузка файлов прямо с компьютера или телефона (перетаскиванием или через выбор файла).
- Слоты: фото первого экрана, фото Ирке для блока «О мастере», галерея кабинета (можно добавлять и удалять снимки, менять порядок).
- Для каждого фото — подпись для доступности.
- Текущие пять фотографий переносятся автоматически, чтобы сайт не остался пустым.

### Контакты
- Телефон, WhatsApp, Telegram, ВК-сообщество, личная страница ВК, Авито, адрес, подсказка «как найти», часы работы.
- Любую ссылку можно скрыть, если она перестанет быть актуальной.

### Тексты страницы
Редактируются все текстовые блоки:
- первый экран (заголовок, подзаголовок, надписи на кнопках);
- «О мастере» (заголовок и абзацы);
- «Почему выбирают» (карточки: заголовок + текст, добавление/удаление);
- «Как проходит визит» (шаги, добавление/удаление);
- «Вопросы и ответы» (вопрос + ответ, добавление/удаление);
- заголовки разделов, текст в подвале и дисклеймер;
- заголовок и описание страницы для поиска (SEO).

## Что увидит посетитель
Внешне сайт не меняется — та же серо-голубая гамма и та же структура. Разница в том, что содержимое теперь берётся из базы, а не «зашито» в код.

## Техническая реализация

- **Включаю Lovable Cloud**: база данных, вход по логину/паролю, хранилище файлов.
- **Аутентификация**: email + пароль, регистрация закрыта; роли в отдельной таблице `user_roles` (`app_role` enum) + security-definer функция `has_role`. Проверка прав только на сервере.
- **Схема БД** (RLS включена на всех таблицах, публичный `SELECT` для `anon` только на опубликованный контент, запись — только админам через `has_role`):
  - `services` — зоны и комплексы: `kind` (`zone`/`complex`), `title`, `description`, `price`, `badge`, `sort_order`, `is_visible`.
  - `site_content` — пары «ключ → значение» (jsonb) для текстов, контактов, SEO, настроек акции.
  - `site_images` — `slot`, `path` в бакете, `alt`, `sort_order`.
  - Миграция включает `GRANT` для `anon`/`authenticated`/`service_role` и INSERT-строки с текущими ценами, текстами и контактами.
- **Хранилище**: публичный бакет `site-images`, чтение всем, запись/удаление — только админам.
- **Маршруты**: `/admin` (вход, публичный) и `src/routes/_authenticated/admin/*` под управляемым гейтом; редактирование через `createServerFn` с `requireSupabaseAuth` и проверкой роли админа внутри обработчика.
- **Главная страница** (`/`) остаётся публичной и SSR: чтение через публичный server fn с publishable-ключом, никакого `requireSupabaseAuth` в loader. Текущие константы (`singleZones`, `complexes`, `whyUs`, `steps`, `faq`, контакты) заменяются данными из БД, с текущими значениями как безопасный фолбэк.
- **UI панели**: shadcn/ui — Tabs, Card, Input, Textarea, Switch, Table, Dialog, sonner-тосты; те же токены дизайн-системы.
